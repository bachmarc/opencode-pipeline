# Story 14-01 — Remove Derived Docs (requirements.md + design.md)

Status: Planned
Feature: eliminate-derived-docs (F-010)

## Context / Purpose

`docs/requirements.md` and `docs/design.md` are derived summaries that duplicate data
from features, stories, and AGENTS.md. They drift constantly (evidence: requirements.md
showed 7 features when 10 existed, multiple wrong statuses). The framework should not
create, maintain, or assert their existence. The Architect's quick-start comes from
`session_recovery.py` (live state) + `FEATURES.md` (feature index) — both always current.

## Requirements

- `docs/requirements.md` and `docs/design.md` are deleted
- No agent prompt, command, template, or script references them as something to create or maintain
- No test asserts their existence
- The Architect prompt directs to `FEATURES.md` for quick context (not requirements.md)
- The Documenter prompt no longer generates/maintains derived summary documents
- `scaffold_project.py` does not create `docs/requirements.md` or `docs/design.md` in new projects
- `prepare_agents_md.py` does not reference requirements.md or design.md in generated References sections
- The AGENTS.md template References section does not list requirements.md or design.md
- README.md references are updated (no "derived summaries" language for deleted files)
- Existing tests pass (modified or removed as needed)
