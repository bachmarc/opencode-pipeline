# Story 08-02 — Architect prompt: features/stories as primary source

Status: Done
Feature: doc-model-reform (F-005)

## Context / Purpose

The architect prompt currently instructs the architect to write requirements into
`docs/requirements.md` (with REQ-IDs) and architecture into `docs/design.md` as
primary sources, then decompose into stories that reference these docs.

With the new documentation model, features and stories ARE the primary source.
The architect creates features (with vision + context) and self-contained stories
(with purpose + requirements + acceptance criteria). The architect no longer manually
maintains requirements.md or design.md — those become Documenter-generated summaries.

The architect still reads requirements.md at session start as a quick-start summary
(generated by the Documenter), but writes into feature/story files.

## Requirements

- The architect prompt must instruct the architect to create features and stories as
  primary documentation (not requirements.md / design.md)
- The architect prompt must reference the new story template (5 sections) and feature
  template (vision + context)
- The architect prompt must NOT instruct writing to requirements.md or design.md
  (those are Documenter output)
- The architect prompt must instruct reading requirements.md as a Documenter-generated
  summary for quick context at session start
- The "Output after Phase 1+2" section must list features + stories (not requirements.md
  + design.md)
- The "Autonomous Design Repair" section must reference feature/story files instead of
  REQ-IDs
- Architecture guidance (function vs connectivity, fakes, integration tests) stays
  unchanged — it moves into the feature/story context, not into a central design.md

## Developer Targets (exactly, no more / no less)

- **`agent/architect.md`** — rewrite the following sections:

  1. **"Your Tasks" section 1 (Gather requirements):**
     - Change from "requirements → `docs/requirements.md`" to:
       "Create feature files (`docs/features/<name>/feature.md`) with vision + context.
       Use the feature template (`docs/features/_feature_template.md`)."
     - Keep: iterative interview, clarify problem/audience/scope, ask don't guess

  2. **"Your Tasks" section 3 (Decompose features & stories):**
     - Change from "STORIES.md index + docs/stories/" to:
       "Create self-contained story files in `docs/features/<name>/stories/<id>-<slug>.md`
       using the story template (`docs/features/_story_template.md`). Each story carries
       its own context/purpose, requirements, acceptance criteria, developer targets,
       and test criteria. Stories do not reference REQ-IDs or Design §-numbers."
     - Keep: use scripts, cut for cheap models, tests before code

  3. **"Your Tasks" section 2 (Design architecture):**
     - Change from "docs/design.md with mandatory sections" to:
       "Document architecture decisions in the feature's context and story requirements.
       Architecture guidance (function vs connectivity, fakes, integration tests) is
       written into the relevant feature/story files, not into a central design.md.
       The Documenter will later synthesize a design.md overview from your features/stories."
     - Keep: all architecture guidance content (separation of function vs connectivity,
       fake interfaces, integration tests, data model, versioning)

  4. **"Output after Phase 1+2" section:**
     - Change from listing `docs/requirements.md`, `docs/design.md`, `STORIES.md` to:
       "Feature files (`docs/features/<name>/feature.md`) + Story files
       (`docs/features/<name>/stories/*.md`) + `AGENTS.md` (repo guidelines)"

  5. **"Autonomous Design Repair" section:**
     - Change "Update traceability (REQ-IDs ↔ design §)" to:
       "Update affected feature/story files"
     - Change "only docs/design.md + affected docs/stories/*.md" to:
       "only affected feature.md + story files"

  6. **"Rules" section — Planning checkpoint:**
     - Change "first create planning (docs: REQ-IDs, design, stories)" to:
       "first create planning (features with vision/context, self-contained stories)"
     - Change "WHAT will be implemented (stories + developer targets)" — keep as-is
       (stories are still the unit)

  7. **"Session Start" section:**
     - Add: "Read `docs/requirements.md` (Documenter-generated summary) for quick
       context on existing features and architecture decisions."

- **No other files changed.** Only `agent/architect.md` is modified.
